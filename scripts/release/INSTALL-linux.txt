Focus Editor for Linux

Extract the archive and put focus-editor on your PATH, for example:
  mkdir -p ~/.local/bin
  install -m 755 focus-editor focus-editor-server ~/.local/bin/
  python3 install-addons.py
  focus-editor ~/projects/my-project
  focus-editor --ui ~/projects/my-project

The default opens a dedicated Chromium app window, without tabs or an address
bar. Install Chromium or Google Chrome with WebGL 2 and working sandbox support.
Each launch uses a temporary private profile with extensions and sync disabled;
the renderer sandbox stays enabled. Use --ui for the native desktop window. Both modes
use the same editor, terminals, Git, and addons; no Node.js or Electron is needed.
Closing the app window warns about unsaved documents, stops the backend, and
removes its temporary profile. Reloads and connection loss retain the session
while the window is alive. External links open in the system browser.

The addon installer requires Python 3.11 or newer. It installs all bundled
addons in $XDG_DATA_HOME/focus-editor/addons/<id> (normally
~/.local/share/focus-editor/addons/<id>), beside the logs directory.
Add --addon github to install only GitHub. Existing addon data and OS-keyring
credentials are preserved; data is stored separately under addon-data/<id>.
Open Addons below Source Control and choose Rescan installed afterward.
The same manager installs individual addons from the release catalog or a
local addon .tar.gz, checks updates, and enables, restarts, or uninstalls addons.

These binaries are built on Ubuntu 24.04 with glibc (2.39 or newer).
They are not static binaries. Use ldd focus-editor to identify missing shared
libraries. Native mode needs an X11 or Wayland desktop and working OpenGL/EGL
drivers. Both modes use local file dialogs through the desktop portal.

Git, Docker, Codex, and OpenCode are separate optional installations.
Configure provider authentication with each assistant's CLI before enabling it.
The editor starts in the background; use --foreground to see diagnostics.
App mode prints its private session URL only in the foreground for diagnostics.
Keep the full URL private. If Chromium cannot start, inspect --foreground output
or use --ui. The launcher never retries with the browser sandbox disabled.
Browser-reserved shortcuts can take precedence; use editor menus or --ui.
Use --version to display the application version without opening a window.
See the project README for features and troubleshooting.

Shared remote server:
  focus-editor-server
  focus-editor-server --bind 0.0.0.0 --port 8999
  focus-editor-server --config /path/to/server.toml

Install focus-editor-server beside focus-editor. The server stays in the foreground,
requires no browser or display, and defaults to 0.0.0.0:8999. Configure its HTTP Basic
Auth login in focus-editor/server.toml in the user configuration directory
(Linux: ~/.config; macOS: ~/Library/Application Support):
  bind = "0.0.0.0"
  port = 8999
  username = "your-login"
  password = "your-password"
Use chmod 600 on this file. FOCUS_EDITOR_SERVER_USERNAME/PASSWORD override file
credentials; CLI bind/port override file values. The old focus-editor --server
flag directs you to the separate binary.

Open http://HOST-IP:8999. App and --ui editors automatically register, including
when the server starts after them or restarts. The Workspaces list remembers
previously opened folders; Add workspace accepts a host folder path. Start opens
a stopped workspace in a browser-only session; Open selects an existing session.
Click Take control to edit; other viewers remain connected. Closing the browser
or stopping the server leaves all sessions running. Restart the server to reattach
to the same unsaved buffers, terminals, and addons. Stop ends a browser-only session
with save/discard/cancel choices for dirty documents. Close local editors from
their own windows. See README.md for configuration and troubleshooting details.
