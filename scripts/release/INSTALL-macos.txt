Focus Editor for Apple Silicon (macOS 11 or newer)

Drag Focus Editor.app to Applications, then open it from Applications.
The editor opens a dedicated app window using installed Chromium or Google
Chrome (WebGL 2 required), without tabs or an address bar. It uses a temporary
private browser profile and keeps the renderer sandbox enabled. For the native
desktop window, run its executable with --ui. No Node.js or Electron is needed.
Closing the window warns about unsaved documents, stops the backend, and removes
the temporary profile. Reloads and connection loss retain the session
while the window is alive. External links open in the normal system browser.
To install bundled addons, run python3 install-addons.py from the
mounted image (Python 3.11 or newer). Add --addon github to install only GitHub.
Open Addons below Source Control and choose Rescan installed afterward. Addons are
installed beside logs in ~/Library/Application Support/focus-editor/addons.
Persistent data is kept separately under focus-editor/addon-data/<id>.
Updates and default uninstall preserve data and OS-keyring credentials.
The Addons manager also installs local addon .tar.gz packages and provides
enable, restart, credential, and uninstall controls. Automatic release catalogs
currently provide Linux packages only.
This download has an ad-hoc signature, not an Apple Developer ID signature,
and is not notarized. macOS may block the first launch. After attempting to
open it, use System Settings > Privacy & Security > Open Anyway if offered.
Do not disable Gatekeeper globally.

Git, Docker, Codex, and OpenCode are separate optional installations.
Configure provider authentication with each assistant's CLI before enabling it.
Finder launches also search ~/.local/bin, ~/.opencode/bin, /opt/homebrew/bin,
and /usr/local/bin after the inherited PATH.

For terminal diagnostics or to open a workspace directly:
  /Applications/Focus\ Editor.app/Contents/MacOS/focus-editor ~/projects/my-project
  /Applications/Focus\ Editor.app/Contents/MacOS/focus-editor --ui ~/projects/my-project
The macOS application stays attached when launched from a terminal.
App mode prints a private session URL there for diagnostics. If Chromium cannot
start, inspect the error or use --ui; the launcher never retries unsandboxed.
Browser-reserved shortcuts can take precedence; use editor menus or --ui.
Use --version to display the application version without opening a window.
See the project README for features and troubleshooting.

Shared remote server:
  focus-editor --server
  focus-editor --server --bind 0.0.0.0 --port 8999
  focus-editor --server --server-config /path/to/server.toml

The gateway stays in the foreground, defaults to 0.0.0.0:8999, and requires no
browser or display. Set username and password in the user configuration file
focus-editor/server.toml (Linux: ~/.config; macOS: ~/Library/Application Support):
  bind = "0.0.0.0"
  port = 8999
  username = "your-login"
  password = "your-password"
Use chmod 600 on this file. FOCUS_EDITOR_SERVER_USERNAME/PASSWORD override file
credentials; CLI bind/port override file values. Open http://HOST-IP:8999 and
log in once to see every live editor for the same user/data directory. Both app
and --ui windows appear automatically. Select one and click Take control; other
viewers observe the same live state. Closing the browser or gateway leaves local
editors running. Restart older editor binaries once after upgrading to register.
See README.md for configuration paths, clipboard behavior, and routing details.
